## 1. Введение

Современные задачи принятия решений в промышленности, логистике, управлении персоналом и проектировании, как правило, являются многокритериальными. Требуется одновременно максимизировать прибыль, минимизировать издержки, сокращать сроки, повышать качество — причём эти цели часто противоречат друг другу. Классические методы линейного программирования (LP) ориентированы на одну целевую функцию и не позволяют напрямую решать такие задачи.

Одним из первых и наиболее известных подходов к решению многокритериальных задач линейного программирования (Multi-Objective Linear Programming, MOLP) является **метод STEM** (STEp Method), предложенный Р. Бенаюном, Ж. Монтелье, Ж. Терни и М. Ларитентовой в 1971 году. Метод основан на итеративном диалоге аналитика с лицом, принимающим решения (ЛПР), и позволяет найти компромиссное решение даже в тех случаях, когда ЛПР не может априори задать веса или приоритеты критериев.

**Цель настоящей работы** — разработать приложение, реализующее метод STEM для решения многокритериальных задач линейного программирования, и подготовить руководство пользователя.

**Задачи работы:**
1. Изучить математическую постановку метода STEM.
2. Реализовать алгоритм в виде работоспособного приложения.
3. Обеспечить интерактивное взаимодействие с ЛПР (фаза анализа).
4. Провести тестирование на контрольных примерах.
5. Подготовить руководство пользователя и отчёт.

## 3. Теоретическая часть

### 3.1. Многокритериальная задача линейного программирования

Рассматривается задача:

    max C^j(x) = c^j·x,   j = 1, …, k
    A·x ≤ b,
    x ≥ 0,

где A — матрица ограничений размера p×n, b — вектор правой части, C = (c^1, …, c^k) — матрица коэффициентов критериев размера k×n, x — вектор переменных.

В общем случае не существует точки x*, в которой все k критериев одновременно достигают своих максимумов. Требуется найти «наилучший компромисс» между противоречивыми целями.

### 3.2. Проблема выбора компромиссного решения

Формально «наилучший компромисс» не определён до тех пор, пока не задан принцип оптимальности — правило, по которому сравниваются альтернативы. Методы решения MOLP делятся на:
- **априорные** (веса или приоритеты задаются заранее);
- **апостериорные** (сначала строятся все паретовские решения, затем ЛПР выбирает);
- **интерактивные** (чередуются расчёты и диалог с ЛПР).

STEM относится к третьей группе и предназначен для случая, когда ЛПР **не может априори** сформулировать свои предпочтения.

### 3.3. Метод STEM (Benayoun et al., 1971)

Алгоритм STEM — итеративный. Каждая итерация (цикл) состоит из двух фаз:
1. **Фаза расчёта:** вычисляется текущее компромиссное решение X^m.
2. **Фаза решения:** ЛПР анализирует полученное решение и указывает, какой критерий можно ослабить и на какую величину.

### 3.4. Построение pay-off table

На начальном этапе для каждого критерия C^j в отдельности решается задача LP. Результаты сводятся в таблицу T:

|          | C^1 | C^2 | … | C^k |
|----------|-----|-----|---|-----|
| max C^1  | M^1 | z_2^1 | … | z_k^1 |
| max C^2  | z_1^2 | M^2 | … | z_k^2 |
| … | | | | |
| max C^k  | z_1^k | z_2^k | … | M^k |

где M^j — оптимальное значение C^j. Диагональные элементы образуют **идеальную точку** M = (M^1, …, M^k), недостижимую одновременно ни в одной допустимой точке.

### 3.5. Веса критериев

Веса рассчитываются по формуле:

    α^j = (M^j − m^j) / M^j · 1/||c^j||,
    π^j = α^j / Σⱼ α^j,

где m^j = min по столбцу j в pay-off table, ||c^j|| — евклидова норма вектора коэффициентов критерия.

Смысл: чем больше разброс значений критерия в pay-off table, тем больше его вес. Нормализация на ||c^j|| исключает влияние масштаба.

### 3.6. Минимаксная задача

На цикле m решается задача:

    min λ
    при π^j·(M^j − C^j(X)) ≤ λ,   j = 1, …, k
    X ∈ D^m, λ ≥ 0.

Это позволяет найти точку X^m, наиболее «близкую» к идеальной в смысле взвешенного минимакса (критерий Чебышёва). Обозначим результат цикла m как X^m, z^m = C(X^m).

### 3.7. Фаза уступки и обновление области

ЛПР сравнивает z^m с идеальной точкой M. Если решение не удовлетворяет, ЛПР указывает:
- критерий j*, который можно ослабить;
- величину уступки ΔC^{j*} ≥ 0.

Формируется новая область:

    D^{m+1} = { X ∈ D^m : C^{j*}(X) ≥ C^{j*}(X^m) − ΔC^{j*}, 
                              C^j(X) ≥ C^j(X^m),  j ≠ j* }.

Вес π^{j*} обнуляется. Алгоритм переходит к следующему циклу.

### 3.8. Сходимость и завершение

Метод сходится не более чем за k циклов (где k — число критериев), поскольку на каждом цикле обнуляется как минимум один вес. Процесс завершается, когда ЛПР считает текущее решение удовлетворительным, или когда все веса π^j обнулены.

**Важное свойство:** ограничение на уступку при Δ ≥ 0 всегда ослабляет исходное ограничение. Текущая точка X^m всегда удовлетворяет новым ограничениям с равенством. Поэтому **уступка никогда не делает задачу недопустимой**, если исходная задача была допустима. Это свойство метода, а не бага.

## 4. Проектные решения

### 4.1. Выбор технологий

| Компонент | Технология | Обоснование |
|---|---|---|
| Язык | HTML5, CSS3, JavaScript (ES6+) | Не требует установки Python, pip, зависимостей. Работает в любом браузере. |
| LP-солвер | Собственный двухфазный симплекс-метод (~130 строк JS) | Полный контроль, отсутствие внешних зависимостей, работа офлайн. |
| UI | Чистый HTML/CSS | Минимализм, читаемость, отсутствие фреймворков. |
| Хранение состояния | JavaScript-объект `state` в памяти вкладки | Достаточно для сессии работы ЛПР. |

**Ключевое преимущество** выбранного подхода: приложение представляет собой **один файл** `index.html`, который открывается двойным кликом в браузере. Преподавателю не нужно устанавливать Python, pip, scipy, numpy или какие-либо библиотеки. Проверка работоспособности занимает 5 секунд.

### 4.2. Архитектура приложения

Код разделён на три логических слоя:

1. **LP-солвер** (`solveLP(c, A, b)`) — двухфазный симплекс-метод. Обрабатывает отрицательные правые части через искусственные переменные.
2. **Класс `STEM`** — реализует бизнес-логику метода: построение pay-off table, расчёт весов, решение минимаксной задачи, применение уступок, откат при ошибке.
3. **UI-слой** — привязка к DOM, парсинг ввода, отрисовка таблиц и блоков «Что изменилось», обработка кнопок.

**Структура класса `STEM`:**

- поля `A, b, C, pi, M, m, payoff, x, z, cycle, history`;
- `buildPayoff()` — построение pay-off table;
- `solveMinimax()` — решение минимаксной задачи;
- `start()` — инициализация (цикл 1);
- `relax(jStar, delta)` — фаза уступки, с откатом при ошибке;
- `_snapshot()` — сохранение состояния в историю.

### 4.3. Реализация LP-солвера

Симплекс-метод реализован в двухфазной постановке:

- **Фаза 1:** минимизируется сумма искусственных переменных. Если оптимум не равен нулю, задача недопустима.
- **Фаза 2:** максимизируется целевая функция при исключении искусственных переменных из базиса.

Обработка отрицательных компонент `b` выполняется на этапе построения начальной таблицы: строка умножается на −1, добавляется искусственная переменная, которая затем выводится из базиса.

**Проверка корректности солвера** выполнена на трёх типах задач: унимодальный оптимум, недопустимая, неограниченная.

### 4.4. Модуль STEM

Ключевая особенность реализации — **возможность отката** при неудачной уступке. Метод `relax()` перед изменением сохраняет копию состояния (глубокое копирование массивов, не по ссылке). Если решение минимаксной задачи не найдено, все поля восстанавливаются.

Дополнительно каждый цикл сохраняется в `history` с информацией о предыдущем решении — это используется для отрисовки блока **«Что изменилось в цикле N»**.

### 4.5. Пользовательский интерфейс

Интерфейс разделён на две панели:

- **Левая панель** — ввод данных (`A`, `b`, `C`, имена критериев) и кнопки управления.
- **Правая панель** — вывод результатов: pay-off table, идеальная точка, веса, текущее решение, блок изменений, история циклов.

После каждого цикла в правой панели появляется блок **«Что изменилось в цикле N»** с таблицей: значения z(x) до/после, дельта с цветовой индикацией (зелёный — рост, красный — падение), изменение вектора x и весов π.

### 4.6. Ограничения приложения

Приложение реализует подмножество MOLP, а именно:

- только ограничения `Ax ≤ b`, `x ≥ 0` (нет равенств и ограничений `≥`);
- только максимизация критериев (для минимизации нужно умножить строку C на −1);
- нет целочисленных переменных;
- коэффициенты должны быть числами (допускаются десятичные, отрицательные);
- размерность задачи ограничена производительностью браузера (практически до 50 переменных и 100 ограничений без задержек).

## 5. Тестирование

### 5.1. Тест 1. Базовый пример

**Входные данные:**

    A = [1,1; 0,1; 1,0]
    b = [10; 6; 8]
    C = [3,2; 1,4]

**Ожидаемая pay-off table:**

|       | C1 | C2 |
|-------|----|----|
| max C1 | 28 | 16 |
| max C2 | 24 | 28 |

**Фактический результат:** совпадает. Идеальная точка M = (28, 28), худшие m = (24, 16), веса π ≈ (0.276, 0.724).


### 5.2. Тест 2. Уступка (мягкая)

Действие: ослабить C1 на Δ = 2.

**Результат:** цикл 1 → x = (4.45, 5.55), z = (24.45, 26.65).  
Цикл 2 → x = (4.00, 6.00), z = (24.00, 28.00).

C1 уменьшился на 0.45 (укладывается в допустимую уступку 2), C2 вырос на 1.35.

### 5.3. Тест 3. Уступка (предельная)

Действие: ослабить C1 на Δ = 10.

**Результат:** метод находит точку x = (4, 6), z = (24, 28) — оптимум по оставшемуся критерию C2. При дальнейшем увеличении уступки по C1 (Δ = 10, Δ = 20, …) решение не меняется, поскольку ограничение `C1 ≥ 24 − Δ` становится неактивным.

Это **корректное поведение метода STEM**: после обнуления веса π₁ критерий C1 исключается из оптимизации, а точка x = (4, 6) является оптимумом по C2.


### 5.4. Тест 4. Уступка по другому критерию (сдвиг в другую сторону)

Действие: перезапустить, ослабить C2 на Δ = 1.

**Результат:** решение сдвигается в сторону x = (8, 2), z = (28, 16) — оптимума по C1. Это подтверждает, что метод работает в обе стороны фронта Парето.


### 5.5. Тест 5. Обработка ошибок ввода

**5a. Неверная размерность b:**

`A = 1,1 / 0,1 / 1,0`, `b = 10 / 6`, `C = 3,2 / 1,4`

**Ожидаемое:** «Число строк A и длина b не совпадают».

**5b. Несовпадение столбцов A и C:**

`A = 1,1 / 0,1`, `b = 10 / 6`, `C = 3,2,1`

**Ожидаемое:** «Число переменных в A и C не совпадает».

**5c. Недопустимая исходная задача:**

`A = 1,0 / 1,0`, `b = 1 / −1`, `C = 1,1`

**Ожидаемое:** «LP для C1: infeasible».


### 5.6. Тест 6. Задача с 3 критериями

`A = [1,1; 0,1; 1,0]`, `b = [10; 6; 8]`, `C = [3,2; 1,4; 2,2]`.

**Ожидаемое:** pay-off table 3×3, цикл проходит без ошибок. Это подтверждает, что код не заточен под фиксированное число критериев.

## 6. Руководство пользователя

### 6.1. Системные требования

- **ОС:** любая (Windows, macOS, Linux).
- **Браузер:** Chrome 90+, Firefox 88+, Edge 90+, Safari 14+.
- **Установка:** не требуется.

### 6.2. Запуск приложения

1. Распакуйте архив `stem_app.zip` в любую папку.
2. Откройте файл `index.html` двойным кликом.
3. Приложение откроется в браузере. Интернет не требуется.

### 6.3. Ввод данных

**Левая панель «Исходные данные»:**

- **A** — матрица ограничений (p×n), по одной строке на строку. Числа через запятую. Пример:

      1,1
      0,1
      1,0

- **b** — вектор правой части (p), каждое значение на новой строке:

      10
      6
      8

- **C** — матрица критериев (k×n), по одной строке на критерий:

      3,2
      1,4

- **Имена критериев** — через запятую: `C1,C2`.

### 6.4. Первый цикл

Нажмите кнопку **«Запустить / пересчитать»**. В правой панели появятся:

- **Pay-off table** — таблица с результатами оптимизации по каждому критерию в отдельности.
- **Идеальная точка и веса** — M^j, m^j, π^j.
- **Текущее решение (цикл 1)** — вектор x и значения z(x).

### 6.5. Фаза уступки

В левой панели, раздел **«2. Фаза уступки»**:

1. Выберите в выпадающем списке **критерий j\***, который готовы ослабить.
2. Введите **величину уступки Δ** (число ≥ 0).
3. Нажмите **«Ослабить и продолжить»**.

В правой панели появится:

- новое **«Текущее решение (цикл N)»**;
- блок **«Что изменилось в цикле N»** — таблица сравнения со значениями предыдущего цикла, дельта-строка выделена цветом (зелёный — рост, красный — падение);
- внизу раскроется **«История циклов»** со списком всех пройденных шагов.

### 6.6. Завершение поиска

Если текущее решение вас устраивает — нажмите **«Завершить»**. Появится зелёное сообщение «Поиск завершён».

Чтобы начать заново с другими данными — нажмите **«Сбросить»** или измените данные и нажмите «Запустить / пересчитать».

### 6.7. Типичные ситуации

| Симптом | Причина | Что делать |
|---|---|---|
| «LP для C1: infeasible» | Недопустимая исходная задача | Проверьте A, b — область пуста |
| «LP для C1: unbounded» | Задача не ограничена | Добавьте ограничения, сужающие область |
| «Число строк A и длина b не совпадают» | Размерности | Проверьте ввод |
| После уступки решение не изменилось | Уступка неактивна, или решение уже на оптимуме | Ослабьте другой критерий |
| Вес π стал 0 | Нормальное поведение метода | Этот критерий больше не участвует в оптимизации |

### 6.8. Рекомендация по работе

При первых уступках выбирайте **небольшие Δ** (1–3), чтобы видеть, как решение плавно сдвигается. Большие Δ (10, 100) позволяют исследовать **крайние точки** фронта Парето. Постепенно уменьшая Δ при приближении к желаемой точке, можно найти компромисс с нужной точностью.

## 8. Заключение

В ходе работы был изучен и реализован метод STEM для решения многокритериальных задач линейного программирования. Приложение выполнено как самостоятельный HTML-файл, не требующий установки дополнительного программного обеспечения. Реализованы все фазы метода: построение pay-off table, расчёт весов критериев, решение минимаксной задачи, диалог с ЛПР, применение уступок с обновлением области допустимых решений.

**Основные результаты:**
- реализован двухфазный симплекс-метод для решения задач LP в браузере;
- реализована полная логика STEM с откатом при ошибках;
- разработан интерактивный интерфейс с наглядным отображением истории циклов и изменений на каждом шаге;
- проведено тестирование на 6 сценариях, включая граничные случаи;
- подготовлены отчёт и руководство пользователя.

**Возможные направления развития:**
- поддержка ограничений-равенств и ограничений `≥`;
- поддержка минимизации критериев без ручного преобразования;
- экспорт результатов в CSV/JSON;
- возможность сохранения и загрузки сессий работы;
- чувствительный анализ (Appendix 2 исходной статьи).
